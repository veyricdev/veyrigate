# fe-admin

Admin console for the SSO IdP: TanStack Start app acting as a BFF / confidential client (plan D2, §6).
Scaffolded by hand in run 41 (A1–A3), no TanStack CLI. Login (A4) is not wired yet.

## Commands

```bash
pnpm -C fe-admin dev            # http://localhost:3000 (strictPort: the seeded redirect_uri uses :3000)
pnpm -C fe-admin build          # dist/client (browser assets) + dist/server (fetch handler)
pnpm -C fe-admin check:bundle   # scan dist/client for server env names (+ BUNDLE_CANARIES)
pnpm -C fe-admin preview        # serves the build on :3000 with NODE_ENV=production (https URLs required)
pnpm -C fe-admin lint | typecheck | test
```

`src/routeTree.gen.ts` is generated by the Start router plugin on `dev`/`build` and is **committed**
(CI typechecks before building). Do not edit it by hand.

## Environment (A2)

Server-only variables, validated by `src/server/env.ts` (T3Env + zod) when the server starts, **not**
at build time (CI builds without any secret). Copy `.env.example` to `.env` and fill the two secrets
(>= 32 chars). Start loads `.env` into `process.env` for `dev`/`preview`.

| Variable | Rule |
|---|---|
| `OIDC_ISSUER` | URL (`https:` when `NODE_ENV=production`) |
| `OIDC_CLIENT_ID` | non-empty |
| `OIDC_CLIENT_SECRET` | >= 32 chars |
| `SESSION_SECRET` | >= 32 chars (reserved for A4, store decided there: DEBT-265) |
| `ADMIN_API_BASE_URL` | URL (`https:` in production) |
| `ADMIN_API_RESOURCE` | URL (resource indicator of the admin API) |
| `APP_URL` | origin only, no path / trailing slash (`https:` in production) |

- Empty strings count as missing. Errors name the variable only, never the received value.
- Invalid env: the error is logged once at startup and every request gets a bare `500`
  (`src/server.ts`); no page renders.
- Only modules under `src/server/**` (and the server entry) import `env.ts`. It carries the
  `@tanstack/react-start/server-only` marker, so importing it from client code fails the build;
  `check:bundle` is the second net.
- No client (`VITE_*`) variables exist yet; add a separate client env when the first one appears.

## Structure (A3)

- `src/routes/` file routes (`__root.tsx`: document shell, layout, error/404/pending components).
- `src/features/<feature>/` feature code (`theme/`: cookie theme, toggle, server-read prefs).
- `src/components/ui/` shadcn components; `src/components/layout|feedback/` app components.
- `src/lib/`, `src/hooks/` shared helpers; `src/server/` server-only modules.

shadcn is used only through `pnpm dlx shadcn@4.21.3 add <component>` (never a dependency). After each
add: pin every dependency it adds to an exact version from the table below (or one released
>= 14 days ago), replace `import { cn } from "cn"` with `@/lib/utils`, and drop `next-themes`.
Local changes to generated components are commented in place (`sidebar.tsx` SidebarInset is a
`<div>`, `sonner.tsx` takes `theme` as a prop, `use-mobile.ts` uses `useSyncExternalStore`).
`src/shadcn-variants.css` vendors the subset of `shadcn/tailwind.css` the components use.

Theme: `theme` cookie (`light|dark|system`, anything else = `system`) read on the server, sets the
`<html>` class; `system` has no class and follows `prefers-color-scheme` in CSS. No inline script.
