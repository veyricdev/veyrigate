### Task 1 [BE] DEBT-142 — thiết kế
- **Cơ chế (chốt)**: Mongo transaction (`connection.startSession()` + `session.withTransaction(fn, { readConcern: { level: 'snapshot' }, writeConcern: { w: 'majority' }, maxCommitTimeMS: 5000 })`, `endSession` trong `finally`) **kèm câu touch chung** — KHÔNG lease/khoá mềm (giả định thời gian), KHÔNG đếm-rồi-ghi ngoài transaction. Không side effect ngoài DB trong `fn` (driver chạy lại `fn` khi TransientTransactionError); audit/revoke chạy sau commit.
- **Điểm sửa**:
  1. `be/src/modules/identity/schemas/user-tenant.schema.ts`: thêm `superAdminGuard: { type: Number }` (BẮT BUỘC có trong schema: mongoose `strict` lột path lạ khỏi update ⇒ `$inc` rỗng ⇒ không có write conflict ⇒ guard im lặng mất tác dụng) + index `{ tenantId: 1, roles: 1 }` (truy vấn guard theo tenant, tránh COLLSCAN trong transaction). Không trả field này ra ngoài (`toAdminUser` map tường minh — giữ).
  2. Provider mới nhỏ trong identity (vd. `SuperAdminGuard` cạnh `UserTenantService`, inject `Connection` + model `UserTenant` + `User`): `runGuarded<T>(write: (s: ClientSession) => Promise<T>)` (bọc transaction) và `assertSurvivors(tenantIds: string[], targetUserId: string, s)`: (a) `updateMany({ tenantId: { $in }, status: 'active', roles: 'super_admin' }, { $inc: { superAdminGuard: 1 } }, { session })` — điểm xung đột; (b) `find` membership super_admin active của các tenant đó, `userId ≠ target`; (c) `users.find({ _id: { $in }, lockedUntil: { $ne: ADMIN_LOCKED_UNTIL } })` (cùng predicate `subjectFailure` 'user_locked'); tenant nào còn 0 ⇒ ném `LastSuperAdminError` (lỗi domain mới, `identity.errors.ts`). "Active" = membership `status:'active'` ∧ `roles ∋ super_admin` ∧ user tồn tại ∧ không admin-lock (khoá tạm do sai mật khẩu vẫn tính active vì tự hết hạn).
  3. `UserTenantService.replaceRoles(ctx, userId, roles, unlessRole?, session?)` và `UserService.adminLock(sub, level, now?, session?)` nhận `session`. `TenantScopedRepository.findOneAndUpdate` thêm `options?: { session?: ClientSession }` (giữ scope tenant + `withoutTenantId`).
  4. `AdminUsersController.setRoles`: actor super ∧ `dto.roles` không chứa `super_admin` ⇒ chạy trong `runGuarded`: `replaceRoles(..., session)` → nếu `before.roles` chứa `super_admin` ⇒ `assertSurvivors([ctx.tenantId], t.id, s)`. Nhánh khác (non-super; grant super_admin) giữ nguyên, không transaction.
  5. `AdminUsersController.lock`: actor super ⇒ trong `runGuarded`: `membershipsOf(target)` (cùng session) lấy các tenant mà target là super_admin active; nếu khác rỗng ⇒ `assertSurvivors(tenants, t.id, s)`; rồi `adminLock(..., s)`. Sau commit mới audit `LOCKED success` + `revokeAllUserCredentials` như cũ (thứ tự run 56/57 giữ; `lockMarkAt` lấy từ doc trả về). Actor non-super không khoá được user có vai trò admin (`assertMayTouchAccount`) ⇒ không cần guard.
- **Hợp đồng lỗi**: `LastSuperAdminError` ⇒ `AdminAuthError.conflict('at least one active super_admin must remain')` (409, mô tả cố định, không id/đếm).
