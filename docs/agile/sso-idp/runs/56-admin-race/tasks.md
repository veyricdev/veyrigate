### Task 3 [BE] (làm trước): DEBT-166 — secret mới tự huỷ nếu client thành admin-capable trong lúc cấp

- `AdminClientsController.issueSecret` (`admin-clients.controller.ts:293`): sau `rotateSecret` và **trước** audit/return, nếu actor không phải super_admin: đọc lại client (`getForTenant`) và chạy lại vị từ của `assertMayModify`. Vi phạm (admin-capable) ⇒ `revokeSecret(clientId, issued.version)` ⇒ audit `CLIENT_SECRET_CREATED|ROTATED` `result:'failure'`, `reason:'admin_granted_concurrently'`, `metadata:{version}` ⇒ **403 `forbidden`**; client biến mất ⇒ revoke version + 404. **Không bao giờ** trả plaintext ở các nhánh này. Đọc lại lỗi DB / revoke lỗi ⇒ revoke best-effort + 5xx, không plaintext (fail-closed).
- Vì sao đủ (không cần transaction/schema): phía super_admin = revoke#1 → update(grant) → revoke#2; phía tenant_admin = check → insert → đọc lại. Đọc lại thấy chưa admin ⇒ insert < update < revoke#2 ⇒ bị revoke#2; thấy admin ⇒ tự huỷ.
- `rotateSecret` đã rút grace của version cũ trước khi biết bị từ chối: chấp nhận (client admin-capable thì revoke#2 huỷ tất cả); ghi comment.
- **Test int `admin-api.int-spec.ts` (barrier bắt buộc)**: (a) giữ tenant_admin SAU `rotateSecret` (spy + promise) → super_admin PATCH thêm `admin` hoàn tất → thả ⇒ 403, body không có `clientSecret`, version đó `revokedAt != null`, audit failure đúng reason; (b) giữ SAU `assertMayModify`, TRƯỚC insert → grant → thả ⇒ 403 tương tự (hoặc version bị revoke#2 — kỳ vọng: không version nào chưa revoke); (c) đối chứng không race ⇒ 201 như cũ; super_admin cấp secret cho client admin ⇒ 201; (d) DB lỗi khi đọc lại ⇒ 5xx, version vừa tạo revoked, không plaintext.
- **Mutation RED**: bỏ bước đọc lại ⇒ (a) 201 + secret sống; chỉ 403 mà không `revokeSecret` ⇒ version còn sống.

### Task 2 [BE]: DEBT-147 + DEBT-153 — lock/unlock nguyên tử + mức khoá

- **Schema** `users`: thêm `adminLockLevel?: 'tenant_admin' | 'super_admin'` (không index, không migration). **Dữ liệu cũ**: `lockedUntil === ADMIN_LOCKED_UNTIL` mà thiếu `adminLockLevel` ⇒ coi là **mức super_admin** (fail-closed: tenant_admin không mở được khoá cũ không rõ nguồn). Khoá brute-force (`lockedUntil` < sentinel) không có mức ⇒ tenant_admin mở được như nay.
- `UserService.adminLock(sub, level)`: super_admin ⇒ `findOneAndUpdate({_id}, {$set:{lockedUntil:SENTINEL, adminLockLevel:'super_admin'}}, after)` (nâng mức). tenant_admin ⇒ filter `{_id, $or:[{lockedUntil:{$ne:SENTINEL}}, {adminLockLevel:'tenant_admin'}]}` set mức `tenant_admin`; miss + user còn + đang sentinel ⇒ đã khoá ở mức cao hơn: **không hạ mức**, vẫn revoke + audit success (idempotent), trả view hiện tại. Lock không còn đi qua `updateStatus`.
- `UserService.adminUnlock(sub, actorIsSuper)`: `findOneAndUpdate(filter, {$set:{failedLoginCount:0}, $unset:{lockedUntil:1, adminLockLevel:1}}, {returnDocument:'before'})`; filter super = `{_id}`, tenant_admin = `{_id, $or:[{lockedUntil:{$ne:SENTINEL}}, {adminLockLevel:'tenant_admin'}]}`. Miss + user tồn tại ⇒ **403** + audit `ADMIN_USER_UNLOCKED failure reason:'locked_by_super_admin'`; miss + user mất ⇒ 404. Audit `UNLOCKED success` **chỉ khi** `before.lockedUntil != null || before.failedLoginCount > 0` (diff từ `before` nguyên tử, bỏ dùng `t.user`). View trả về dựng từ `before` + các trường đã xoá. `resetFailedLogins` không còn ai gọi ⇒ xoá (hoặc giữ nếu còn caller).
- Audit lock thêm `metadata.level`. `seed-dev.ts` `$unset` thêm `adminLockLevel`. `setPassword`/`clearFailedLoginsIfUnlocked`/`recordFailedLogin` không đổi (đã không xoá sentinel) — pin: reset mật khẩu user super-lock giữ nguyên `lockedUntil` + `adminLockLevel`.
- Không đổi view/FE run này (DEBT-336 `lockKind` giữ mở; FE thông điệp riêng ⇒ DEBT-416); 403 dùng mapping `forbidden` sẵn có của fe-admin.
- **Test int `admin-users.int-spec.ts`**: (a) super_admin lock → tenant_admin unlock ⇒ 403, user vẫn khoá, audit failure; super_admin unlock ⇒ 200; (b) tenant_admin lock → tenant_admin unlock ⇒ 200; (c) tenant_admin lock user đang super-lock ⇒ 200, mức vẫn `super_admin`, tenant_admin unlock tiếp ⇒ 403; (d) sentinel cũ không mức (ghi thẳng DB) ⇒ tenant_admin unlock 403, super_admin 200; (e) brute-force lock ⇒ tenant_admin unlock 200; (f) **race barrier**: lock, rồi K=5 unlock song song (barrier giữ mọi request tới ngay trước lệnh ghi rồi thả cùng lúc) ⇒ đúng **1** `UNLOCKED success`; (g) **race barrier**: unlock (super) đọc/giữ trước ghi, lock chen vào hoàn tất, thả unlock ⇒ user mở khoá VÀ có đúng 1 `UNLOCKED success` (ghi sau `LOCKED`); (h) user chưa khoá, failedLoginCount 0 ⇒ unlock 200 không audit.
